# CEO demo — 7 November 2026

This release removes the duplicate project inquiry link from chat. There is one pink action: **Projekt vorstellen**, changing to **Projektangaben fortsetzen** once the visitor starts. English uses **Tell us about your project / Continue your project details**. The six-step form consistently calls its content project details; it no longer calls them a draft. Existing context, editing, resuming and delivery safeguards are preserved.

The previously tested conversation-clear button remains beside expand and close. Clearing requires confirmation and cancels pending answers.

## Shareable page and media

The `/demo` route contains the videos, a transcript of the workshop conversation, and the actual website widget. `/preview?lang=de` remains the interactive preview. Both run on the existing host; no video platform, analytics, subscription or additional runtime dependency is added.

- `/demos/forju-compass-demo-de.mp4`: 45 seconds, 2560 × 1600, H.264, 30 fps, silent.
- `/demos/forju-compass-projekt-de.mp4`: 52 seconds, same format, project idea → prefilled form → edit → return to chat → resume → six-step review → return to browsing.

These are recordings of a real isolated Chrome browser. The public ForJu homepage and workshop article were loaded read-only. Compass was inserted into that browser only, with its real local production `/api/chat` path and `COMPASS_LOCAL_ONLY=true`. The visible **Website-Vorschau** label and page caption identify the preview. Only typing and loading intervals were shortened; answer text was not replaced or generated for the recording. No production website was changed and no email or project was sent.

The first video asks:

1. „Welche Workshops bietet ihr für Schulen an?“
2. „Und wie melde ich meine Klasse dafür an?“

It opens [the cited school-workshop article](https://forju.at/de/projects/schulworkshops) and shows its Anja Hofer contact paragraph. The second video uses a synthetic class air-quality project. Logos come from the existing Compass assets.

## Known limitation

Project email delivery is **not enabled**: `/api/project-submission` reports `direct:false` without an authorized sender. The form and demo disclose this, retain the visitor's details and never show a successful receipt. Configure an authorized sender under the existing server settings before presenting project delivery as available. No real mailbox delivery was tested for this release.
