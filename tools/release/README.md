# Repeat the Compass release audit

From the repository root, run `npm run test:release` with a **local Docker Engine** running. It builds a dependency image on first use, then builds and starts the actual Next production app inside a fresh container. Allow several GB for the test images. The host needs Bash, Git, tar, npm and Docker. Results and exit status are printed at the end. Raw evidence and a human-readable summary are under `work/release-audit/<run>/`. No cloud credentials or mail account are needed. No hosting or deployment command runs.

The preparation phase downloads pinned public images and npm lockfile dependencies. Tests run with Docker networking disabled (`--network none`). ZAP, k6 and Promptfoo share that container's loopback namespace. No host ports, Docker socket, production env files or production database are mounted. Source and approved public assets are copied from the current checkout, including pending source edits. Keep the checkout/commit alongside the report to reproduce it. The QA HTTPS parent is added at **test build time only**. Do not deploy this build or its fixture settings to Render.

## What is real and what is simulated

* **Answers:** Promptfoo calls the real `/api/chat`, carrying prior user and assistant messages and the returned topic. The reference in [sources.md](sources.md) comes from the published articles. [Case definitions](quality/cases.cjs) are separate from implementation. An assertion checks both content and the supporting URL. No LLM judge is used. `final-answers.jsonl` preserves all turns for reviewing incidental claims and tone. `AUDIT_PHASE=baseline` runs the development questions only. The default full run includes the reserved questions. Once examined, those questions become regression cases, not fresh holdouts for future releases.
* **Browsers:** Chromium, Firefox and WebKit run their real Linux browser binaries. Mobile WebKit uses an emulated phone viewport. In addition to the existing suite, a local HTTPS website installs the actual embed script. Another origin attempts the same installation and must be denied by CSP. Official source navigation resolves to a labeled offline destination under the expected URL. It is not a live link check. axe-core scans the project review and feedback error states as well as existing chat/initial draft states. It supplements manual and keyboard checks.
* **Delivery:** The real feedback route and Resend SDK point at a loopback receiver using a synthetic key. The receiver stores one message, loses the first acknowledgement, and deduplicates the retry by idempotency key. Tests verify the opt-in and opt-out payloads, recipient, contents, retry count, single receipt and focus return. Each browser trial represents a different synthetic ingress client. Project send is deliberately unavailable in the release fixture. A second instance of the same build enables a synthetic sender and tests consent, lost acknowledgement and exactly one accepted draft through the real route and SDK. The browser tests also cover a simulated provider recovery. No message goes to a real email address.
* **Privacy and security:** Browser traffic from the added journeys is checked against local origins. Node HTTP clients in the app are observed for unintended egress. The network namespace enforces isolation independently of these checks. The scanner spiders and passively evaluates the public HTML/asset surfaces. Hooks include the embed and API status page. An explicit gate rejects unreviewed medium/high findings. The allowed inline **style** warning is documented in the release report. This is not a penetration test.
* **Load:** k6 uses distinct synthetic client identifiers and the same production SQLite quota implementation. The disposable database is reset **before** the phase. Five spaced requests, one per-visitor quota check and a 20-request parallel burst exercise the shared minute limit. A final request waits out the real Retry-After window and must succeed without a reset or restart. Counts and normal/burst p95 are in `load.json`. Burst timing includes fast refusals. Results are for one local instance.
* **Model boundary:** This is a catalog-only audit. A live AI-backed release needs a separate evaluation of retrieval, grounding, privacy and cost. The isolated suite never downloads a model or falls back to a remote judge.

The deployment decision and smallest outstanding checks are in [the release report](../../docs/release-audit.md).
